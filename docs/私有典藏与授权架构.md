# 私有典藏与授权架构 v0.4

## v0.6 用户澄清：本文件仅为未来预留

当前建设完全基于网上公开信息的研究库，可正常检索、AI整理、建立正文及索引。下面所有授权、分级、加密与受限处理规则仅是未来可能上架软件/网页或实际接入机密资料时的方案，不对当前公开资料工作生效。是否实施及具体方式届时再定。

## 定位与本轮范围

未来产品阶段可考虑发展为“学院师生使用、老师审定范围的私有学习与典藏系统”。知识目录保持完整，访问范围独立于目录分类。宗教内容是否限阅、需要什么修学条件，依具体资料及老师决定；系统不把一句概括扩写成所有藏传资料都必须采取同一权限的规则。

用户已明确今后可能提供本地机密经文。本轮仅预留结构并更新后续工作约束：尚未接收机密材料、建立加密卷、部署登录系统或改变远端可见性。后续资料接入以真实可验证的保护能力为前提。

## 三个边界

1. **知识与代码仓库**：保留现在的主题框架、模板及将来系统代码；若未来实施私有方案再调整可见性。GitHub协作者通常可取得仓库内容，因此学生阅读不靠成为仓库协作者实现。
2. **私有内容库**：放原始PDF、音频、OCR、译文、机密书目与授权登记；位于Git工作目录之外的加密存储，使用不暴露书名的不透明对象ID。仓库内仅留无敏感内容的结构示例。
3. **授权阅读服务**：师生登录后，由服务端依据身份、资料策略和老师授权决定可见对象与操作。私有仓库与网页读者权限分别管理。

规划中的内容库结构（只是示意，未创建）：

```text
<仓库之外的加密保管区>/
├── intake/          新材料待审定，默认仅保管人员可见
├── originals/       原件，保留校验与来源
├── catalog/         私有书目与敏感元数据
├── derivatives/     OCR、译文、缩略图、字幕、摘要
├── indexes/         受限检索与向量数据
├── policies/        内容访问与处理策略
├── grants/          老师授权及其撤销记录
├── audit/           访问与操作审计
└── backups/         加密备份记录或加密副本
```

上述目录名本身不提供加密。实际启用时选择成熟存储与密钥管理方案，密钥与密文分离，完成锁定、解锁、恢复和备份演练；不自创加密算法。系统解密服务所在环境是信任边界，不能只因磁盘加密就称运维人员绝不可能读取。若后续要求连服务端管理员也不能读，需重新设计客户端密钥和搜索能力。

## 内容分级与操作授权

| 策略 | 默认阅读范围 | 说明 |
|---|---|---|
| pending_review | 指定保管者/审定者 | 新导入或范围不明时默认状态 |
| academy_internal | 已核验且有效的本院师生 | 须先由资料负责人批准为校内共享 |
| teacher_restricted | 符合老师明确授权的人或班组 | 师生身份只是必要条件之一 |
| local_sealed | 指定本地保管者 | 默认不进入网络阅读或AI处理流程 |

公开可获得性用source_visibility另存，不能绕过上述策略。本未来方案不预设面向公众的阅读层；将来若老师允许公开摘编，再单独形成经审定的导出对象。

“查看目录、读正文、听音频、下载、打印、导出、编辑、AI处理、再授权”分别控制。只允许看某个条目不等于允许下载其所有版本；系统管理员不因技术角色自动获得教学授权。

## 授权流程

师生身份由院方或老师指定的人员核验 → 老师在自己的管理范围内选择对象及允许操作 → 记录授权期限和适用条件 → 每次请求重新检查当前权限 → 到期、离院停用或撤销后停止访问。

授权记录包含grant_id、授予者、受授人/班组、资源及版本范围、操作、起止时间、状态、审定依据引用。修学条件由老师确认并记录是否符合，AI不能依据履历自行认定已获灌顶、传承或其他资格。材料的宗教授权与著作权/再分发权限分开保存。

班组成员变动、资源新版本是否继承授权必须有明确策略；默认新版本不自动扩大可见范围。正式上线前明确由谁可任命授权老师和处理授权争议，防止任何账号自行给自己发权限。

## 阅读、搜索和派生材料

权限检查覆盖页面、API、PDF、图片、音视频分段、搜索建议、结果数量、标题、摘要、图谱与下载。不能先把全部内容或搜索索引发送浏览器再用界面隐藏；未获准知道存在的资料连标题和计数也不泄露。

OCR、译文、摘要、字幕、音频、嵌入向量、缓存和备份继承来源限制。多来源组合取约束交集，不因生成新文件变成普通资料；降低限制需要重新审定。撤销时撤回会话/访问能力，失效链接与缓存按设计同步处理，避免长期直链绕过权限。

“只读”可限制服务端下载入口，无法保证获准阅读者不能截图、拍照或记录；系统不承诺这种绝对防复制。撤销也无法删除已经合法下载到他人设备的副本，导出权限应单独决定。

## AI与低成本模型的边界

继续使用Luna检索公开外部来源；这不授权其读取将来的机密保管区。pending_review、teacher_restricted、local_sealed资料默认禁止发送云端模型、在线OCR、翻译服务或外部搜索，包括标题、摘录与附件路径。

“本地文件”不意味着本地推理。读取文本到云端对话上下文也属于外发。将来如需AI处理，先确定具体资料、允许的处理环境与操作，再使用相应工作流；local_sealed默认连本地AI也不自动启用。派生输出不能写回普通工作区或混入公开检索任务。

## 审计、备份与恢复

记录谁何时执行了哪些授权、阅读和导出操作，日志用对象ID，避免抄入经文正文；审计日志自身限阅并约定保存周期。备份继承权限与加密要求，制定密钥遗失和负责人交接办法，验证能够恢复后再接收不可替代原件。

## 既有公开项目怎样过渡

本地框架继续设计，不因目录完成就默认公开发布。原lama-mumtso可能已有公开历史、附件或其他副本；以后改私有只限制后续访问，不能保证收回既有副本。旧项目具体内容仍需逐项决定保留、迁移或停止公开。

保留Git历史的迁移建议只适用于确认可进入目标仓库的内容。机密经文绝不通过subtree或普通commit导入；若旧历史存在限制内容，迁移方案须先调整，不能盲目保留全历史。

## 实施顺序与验收

1. 当前：继续建设网上公开资料库；本文件仅保留可选接口和设计，不要求先实施授权或加密。
2. 本地典藏试点：先用虚构样本验证加密存储、派生文件去向、备份和恢复，再接入真实机密材料。
3. 身份和授权试点：老师、获准学生、未获准学生、离院账号分别验证资源权限；校验越权直链、搜索侧漏、新版本与撤销。
4. 小范围阅读：实际权限与操作范围验收后，再交付PDF/音频阅读与检索。
5. 后续AI：在明确获准的环境内试点，验证输入、输出、缓存与索引没有越出资料策略。

工程依据：[OWASP授权建议](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)用于默认拒绝和逐请求鉴权；[OWASP加密存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html)用于成熟加密方案和密钥管理原则。具体实现选型在实施时复核。
