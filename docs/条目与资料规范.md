# 条目与资料规范

## 主档和登记表

正文使用 Markdown；关系与来源使用 UTF-8 JSONL，每行一个对象。ID 在创建时分配，永久不随标题改变；展示名称和路径可以调整。推荐前缀：人物 P、机构 I、传承 L、文献 W、教理 C、尊格 D、故事 N、法物 O、仪轨 R、法会 F、事件 H、术语 T、来源 S、版本 E、媒体 M、主张 Q、关系 X，后接六位序号。分配ID由主维护者集中处理；执行模型提交候选临时ID，合并时统一映射。

| 文件 | 最低字段 |
|---|---|
| entities.jsonl | id, type, title_zh, title_bo, aliases, path, status |
| sources.jsonl | id, title, url, publisher, author, published_at, accessed_at, source_type, access_status, rights_status |
| editions.jsonl | id, work_id, languages, translator, publisher, date, catalog_ids, source_ids, file_path, sha256, completeness, review_status |
| media.jsonl | id, kind, url, platform, channel, language, work_id, edition_id, coverage, duration, source_ids, checked_at, review_status |
| claims.jsonl | id, subject_id, statement, claim_type, evidence, review_status |
| relations.jsonl | id, subject_id, predicate, object_id, valid_from, valid_to, tradition, evidence, review_status |

`evidence` 是数组：每项含 source_id、locator、简短摘录或释义；PDF定位同时记录文件页码与印刷页码（如有），音视频记起止时间，网页记章节标题。字段未知填 null；“未知”和“不适用”用附加 note 区分，不填看起来合理的值。时间允许年、年月、完整日期，附 precision；不能把模糊时间补成具体某日。关系字段只适用于有时间性的关系时才填起止时间。

实体状态：stub / researching / review_required / reviewed。主张类型：documented_statement（文献明确陈述）/ traditional_narrative（传统叙事）/ attributed_teaching（署名教言）/ editorial_summary（编辑归纳）。它们说明陈述性质，不是自动的真假评级。争议用 competing_claim_ids 和说明记录。

## 藏文、汉文与版本

- 作品 W 与版本 E 分开：一部作品可有多个藏文版、汉译本与双语合刊。同名不自动认定同书。
- 藏文保留 Unicode 正文；原文件不改动。用于搜索的规范化副本另存；Wylie 与汉字音译各自标明来源及审校状态。
- “藏汉双版本”是目标；缺一侧明确写“仅藏文”“仅汉译”或“版本关系待核”。AI翻译只能作为工作译文，不充当原文或权威译本。
- 版本比对至少核查题名、作者/译者、篇章结构、首尾题记；对照优先按章节/偈颂/段落，不按PDF同页码强行配对。
- PDF图像扫描、可提取文本、OCR、人工校订是不同状态。保存原件与 SHA-256；提取文本和OCR各自记录工具/日期与抽查结果。
- 原文PDF记录完整性及页数；只有书目或外链不能计入“全文已取得”。

## PDF、音频与YouTube

公开可访问不等于可再分发。每个文件记录权利说明或许可出处；依据不足时先保留官方链接、版本和页码。确认可以入库的小型PDF随仓库保存；大型可分发媒体放对象存储或Release，仓库留稳定URL、校验值和元数据。以后按实际规模选择托管，不先引入大文件依赖。

YouTube优先保留视频链接及 video_id，网页层再生成嵌入；默认不下载。记录频道、标题、发布时间、访问日期、语言、片段起止、关联版本。念诵、讲解、法会实录、配乐必须分开标记。不因标题相同便认定全文念诵；无法试听时明确未核听；失效时保留历史记录和替代链接，不悄悄替换成别的版本。

`review_status` 可为 not_checked / metadata_checked / sampled / fully_checked；媒体抽查还要记录抽查时间段。此状态仅说明核查范围，不替代对演诵者身份或版本的证据。

## 核心观点与故事

主要观点每条包含：白话概括、对应段落/偈颂、必要短引、解释归属、相关概念。只拿到目录或片段时，限制为“已读部分导读”，不得写全书结论。讲记观点与根本文本观点分开。

故事记录最早已找到的出处（不声称绝对最早）、当前所读版本、叙述者、异本。历史材料、传记传统、授记及编辑解释分别呈现，保持尊重而不把宗教叙述转写成已经独立证实的历史事实。

仪轨条目记录公开来源载明的修学条件和使用语境；不由模型补造步骤、咒文或师承。没有公开正文时建书目入口。

## 最低发布门槛

有稳定ID、清楚的文类/身份、可访问的来源、关键陈述定位、未解决问题说明。待审稿可保留在候选区；不得被统计成已核验条目。人物当下职务须记录来源时间及最后核查日期，旧页面里的“现任”只能代表该页面时点。

未来校验器检查：ID唯一、引用可解析、文件路径存在、链接状态与日期、必填字段、文件hash、被标为藏汉对照的版本是否两侧齐全。内容正确性仍需阅读和审校。


## v0.2：身份、路径与空间扩展

沿用 entities.jsonl 登记，新增实体类型与前缀：身份/角色 A、课程 U、制度路径 J、地点/功能区 G、建筑 B、地图 K。机构下的建筑不必伪装为独立机构。新增字段只对相应类型必需；未知记null与原因。

- 身份/角色：category（参与/受戒/教学资格/尊称/传承身份/管理职责）、tradition、institution_id、授予/认定依据、语境。人物通过带证据和时间的关系关联身份。
- 路径：institution_id、适用群体、适用时期、来源类型、steps；每一步包含前提、行动、确认主体、可能结果、证据和未知项。区分制度材料与个人案例。
- 课程：institution_id、语言、适用群体、时期、作品ID、先修关系及其来源。
- 地点/建筑：institution_id、名称异译、geometry或位置描述、coordinate_system、accuracy、功能标签、反映时期、证据；不明坐标系的数据不得混合绘制。
- 地图：source_ids、反映时期、制作日期、底图来源与许可、坐标系、比例/精度、图例、map_type（历史图/实测图/资料整合图/概念示意）。不将概念示意输出为导航地图。

新增关系：人物—具有身份→角色；人物—完成学习→课程；课程—使用→文献版本；建筑—属于→机构；建筑—位于→地点；活动届次—发生于→建筑/地点。各关系继续使用evidence与有效时间；不得仅靠标题或相邻位置推断。

现行政策或访问状态另设checked_at、valid_from/valid_to（未知可null）、issuing_body、scope及current_status。旧文献能支持历史记录，不能因访问日期更新便成为最新规则。


## v0.3：三语词条、句子与交流事件

术语继续使用T前缀；entity.type可分term、phrase、symbol，互相引用但不重复分配同一概念。词表是词条ID的有序选集，不另建重复正文。

- 词/句：text_bo、meaning_zh、meaning_en、sense_note、usage_context、register、wylie、pronunciations、example_ids、source_ids。pronunciations每项包含variety、notation_system、transcription、audio_media_ids、speech_mode（口语/诵读）、review_status。unknown字段填null，不自动补藏文或音标。
- 审校分开：meaning_review、pronunciation_review、usage_review，均附reviewer_or_reference与日期。机器检查通过不等于母语审校通过。
- 音频沿用media.jsonl，绑定具体词/句ID、口语变体、speaker_source、normal/slow、human/synthetic、许可、时间戳与核听范围。
- 符号：Unicode或图像来源、名称与语境、释义证据、相关对象ID；同一图形的不同解释分别记录。
- 交流事件沿用H事件ID：participants、organizer_ids、institutional_capacity（individual/institutional/unverified）、event_type、日期地点、成果与evidence。机构合作关系需专门证据，不从事件共现自动生成。
- 宗教比较：每个比较点列各方自述来源、比较维度、适用传统与时期、编辑归纳；关系图的每条边标明源流/影响/合作/对话等类型。


## v0.4：访问策略与机密元数据（未来预留，当前不启用）

未来启用受限系统后，每条实体、版本、来源、媒体及派生对象关联policy_id与classification（pending_review / academy_internal / teacher_restricted / local_sealed）。资料公开可获得性另记source_visibility；未来受限系统中无分类的新内容默认pending_review。当前网上公开资料不要求这些访问字段，不以老师授权为入库条件；review_status仅表示内容审校。

私有内容库另存策略、授权和身份登记，字段包括owner_ref、teacher_approval_ref、allowed_actions、processing_policy、retention_policy、derived_from、policy_version。敏感标题、原始路径、人物身份记录及授权依据不写进普通仓库中的90登记表；在那里仅保留规范或非敏感样本。

processing_policy注明local_only、external_processing_allowed、allowed_processors和授权依据；机密材料的外部处理默认false。grant与resource分开管理，审批元数据不等于已经执行权限。多来源派生对象必须满足全部来源约束。

当前JSONL设计面向离线编辑；将来多用户授权系统需使用支持事务、版本和审计的持久存储，不直接把Git中的可编辑JSONL当线上权限数据库。


## v0.5：器物与习俗记录

器物沿用O实体ID，补充holding_institution、accession_number、catalog_url、catalog_label、material_claims、dating_claims、provenance、function_claims及各自证据。未知材质不填确定值；collection记录不自动转为科学检测结论。标题中的材料称谓不能代替material_claims的依据。

习俗主档可使用entity.type=custom和新增V前缀，记录region、community、period、description_sources、variation与institution_links。媒体增加media_sensitivity=ordinary/explicit_human_remains/unknown；它是展示标记，不代替policy_id和访问权限。


## v0.7：馆藏与历史日期

对象复用O/W/E等现有ID；收藏机构使用I。馆藏号与机构ID联合辨识对象，历史别号和借展号存aliases，不能仅因题名相同合并。supposed_origin、creation_date、acquisition_date、current_holder与exhibition_location分别记录并附证据。定年用区间、precision和attribution_note保留不确定性。

档案来源增加archive_id、collection、series、box_or_folio及locator；题记抄录与翻译分别标记审校。历史事件用H，关联period_labels、historical_place_names与date_evidence；政权与宗教分期标签仅作索引，不代替事件证据。
