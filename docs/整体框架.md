# 整体框架 v0.8

## 1. 总体决策

采用一个主仓库 `David0936/lama`。以主题目录组织阅读，以稳定 ID 和带出处的关系连接条目。先使用 Markdown 正文和 JSONL 登记表，不提前引入数据库或图数据库；以后网页、全文搜索、关系图均从这些文件生成。

一期以门措上师、法王如意宝、喇荣五明佛学院及相关宁玛传承为中心，但不把学院等同于整个教派，也不把学院课程都归为某教派专有。关于喇荣的机构介绍及法王背景可先从[机构介绍](https://www.khenposodargye.org/about/larung-gar/)和[法王生平讲座](https://www.khenposodargye.org/talks/2017/10/life-work-khenpo-jigme-phuntsok-rinpoche-tibetan-buddhist-master-modern-china/)核查。此处是收录范围设计，不是完整历史结论。

读者说的“佛经”作为总入口，内部区分经、律、论、续、伏藏文献、仪轨、祈愿文、教言、讲记、传记。文类可以多标签，具体归属有出处后再确认。“主要表达观点”同时提供白话导读和原文定位，区分文本观点、某位讲授者解释与编辑归纳。

## 3. 人物与各类内容怎样关联

每种内容只有一个主档。人物页展示其作品、师承、活动；作品页展示不同版本、讲授者、念诵和核心观点；法会页引用使用的仪轨、尊格、法物、举办机构和具体届次。

关系必须有类型，不能用一个含糊的“相关”替代：

- 人物 → 创作/翻译/讲授 → 作品。
- 人物 → 任职于 → 机构，附职务名称与起止时间。
- 人物 → 从某人领受某法 → 具体传承，附文本或法门范围。
- 作品 → 阐释 → 主题，附章节定位。
- 念诵媒体 → 对应 → 某版本或某段；不能只关联一个同名作品。
- 法会届次 → 使用 → 仪轨；仪轨 → 涉及 → 法物与尊格。
- 故事 → 讲述 → 人物/尊格；“化现”“前世”“眷属”等说法附传统、叙述者和出处。

佛、菩萨、本尊、护法等分类保留传统差异和多重角色；不画成统一血缘树。不同故事中的化现、师徒、象征对应等关系分别展示。宗教叙事可以完整收录，其陈述类别与历史事件区分。

## 4. 每类条目要回答的问题

| 类型 | 固定内容 |
|---|---|
| 人物 | 是谁、异名、生平、教言、著作、师承、机构角色、叙事与争议 |
| 机构 | 地点、名称沿革、教育/修学、人物任期、关联法会、历史事件 |
| 教派/传承 | 起源、范围、代表文献、具体传承链、不同支系与解释 |
| 文献 | 是什么、什么版本、藏汉文本、核心观点、谁讲过、如何念诵 |
| 教理 | 概念定义、原文依据、各家解释、易混概念、延伸阅读 |
| 尊格 | 类别、名称、形象、象征、相关文献、故事与传统差异 |
| 故事 | 原出处、谁讲述、情节概要、异本、教义解释、关联人物 |
| 法物 | 名称、形制、图像、使用场合、象征意义、不同传统差异 |
| 仪轨/修持 | 名称、背景、公开文本、仪节与意义、出处所载适用条件 |
| 法会 | 宗教意义、仪轨、参与方式的来源说明、举办方、历史届次 |
| 历史事件 | 时间精度、地点、人物、来源分歧、相关文献 |
| 术语 | 藏文、汉译、Wylie、异译、上下文含义、发音资源 |

## 5. 读者的四种路线

1. 从人开始：法王如意宝 → 生平 → 学院 → 门措及其他人物 → 教言与著作。
2. 从经开始：作品 → 核心观点 → 藏汉版本 → PDF → 对应念诵 → 相关解释。
3. 从法会开始：法会 → 为什么举行 → 仪轨 → 尊格/法物 → 历届记录与视频。
4. 从问题开始：“这些佛之间是什么关系？”→ 尊格分类 → 具体故事版本 → 原典出处 → 不同传统解释。

后续网站可提供人物卡、经典阅读器、时间线、地图、关系图、藏汉搜索与YouTube嵌入。本轮只设计数据和目录，不先建一套难以维护的网站。
