# 分阶段执行与模型分工

## 责任

本轮由当前 GPT-6 主模型负责架构。后续使用自定义 `luna_worker` 执行范围明确的资料发现、元数据抽取、链接与文件核验、候选条目整理。模型能力和可用性以实际运行环境为准，不在这里声称某型号永远最新或价格固定。

高能力主模型保留：范围与分类决策、同名实体消歧、藏汉版本认定、传承关系与争议审校、核心观点综合、迁移集成和发布验收。涉及藏文校勘，AI审阅不能冒充藏文专家审定。执行模型不能自行扩展成“检索整个藏传佛教”。

## 阶段与完成判据

| 阶段 | 工作 | 完成判据 |
|---|---|---|
| 0，本轮 | 框架、目录、数据约定、迁移设计、任务模板 | 可审查文件已落地；不填充未经研究的内容 |
| 1 | 门措项目迁移与统一资料登记 | 迁移方案全部验收项通过 |
| 2 | 小样本验证：法王人物、学院角色、文献版本、媒体 | 3–5部候选文献和1–2条媒体走完来源到关联链；缺失项如实登记 |
| 3 | 扩展人物、教理、尊格、故事、法物、仪轨与法会 | 每批5–10条候选，经主模型审校再合并 |
| 4 | 全文搜索、藏汉阅读、时间线与关系图 | 能沿关系回到原文，搜索区分全文与书目线索 |
| 5 | 持续补缺 | 处理缺口和失效链接，保留版本及修改记录 |

阶段2的作品不提前凭知名度选定为“该院必修/该派核心”。先找到课程、讲授或修持来源，再选择有代表性的样本；双语完整与仅单语材料分别记录。

## 成本与停止规则

每批约定来源上限、实体上限和时间上限；建议初始30分钟或10个来源先到即返回。每批输出检索词、访问过的URL、所得证据与空缺，减少下批重复查找。连续两个入口无法获取同一资源时登记访问阻碍，转找公开替代；不靠增加无关网页凑数量。

低成本模型读原始材料后交付带定位的候选稿；主模型优先核查身份、时间、版本、关系和观点归属，不重复全网检索。来源错误、缺定位、同名未消歧时退回对应小项。

采用AGENTS中的六段式委派格式；每个执行者只写自己的候选批次目录，不修改已发布正文、共享登记表或别人的文件。主模型审核修改文件、验证证据、假设、风险与阻碍，再统一分配ID和合并。

## v0.4：私有典藏约束与后续工程

当前全部批次基于网上公开输入，可正常检索和AI整理，无需老师授权或加密。以下工程仅为未来上架产品或接入机密资料时的预留，不是当前任务的前置阶段。

后续工程顺序：虚构材料的本地加密存储试点 → 身份/老师授权原型 → 权限与撤销测试 → 小范围阅读 → 获准环境中的AI。首个工程批次只能用虚构样本；真实原件在存储、密钥恢复和处理边界验证后接入。当前不启动部署或更改远端可见性。
